# xBot project context

- Canonical Chat AI consolidation plan: `.hermes/plans/2026-07-17-xbot-chat-ai-consolidation.md`.
- Develop and validate in this local repository. Do not modify or deploy the production VPS unless explicitly requested.
- 9Router, xBot Agent, and OnchainOS service endpoints are private/internal trust boundaries. Reject public or credential-bearing URLs before sending service credentials or signed tenant context.
- Chat AI has one server-owned 9Router connection. `ROUTER_URL` is the private service root without `/v1`, and `ROUTER_SECRET` is the shared tenant HMAC secret. Discovered Claude/Codex/Antigravity names are upstream metadata, never direct browser providers or credentials.
- Android/Termux 9Router is a separate runtime and read-only reference only; xBot uses its own bundled `services/nine-router-sidecar` behind tenant-signed internal APIs. User provider connections and OAuth/device-login credentials remain tenant-scoped in that bundled sidecar and are never copied from Android or stored in browser storage.
- The 9Router runtime is fail-closed across restarts: `ROUTER_ENABLED=true` permits owner-controlled ONE Connect, but inference remains disconnected until the owner model-discovery probe succeeds. Disabling the flag is the rollback and does not revive retired BYOK/multi-provider routes.
- A xBot agent cancellation is a terminal non-completion state: do not emit `done`, persist an assistant completion, or fall back to 9Router. A caller abort must stop the upstream xBot agent run.
- Once xBot agent has accepted/created a run, any subsequent stream failure must fail closed: request cancellation best-effort and never fall back to 9Router, because the xBot agent run may still be executing and fallback could duplicate side effects.
- OnchainOS writes are default-deny and require exact tenant/user/run/tool-call/idempotency/tool/args binding, successful simulation, unexpired explicit confirmation, and replay protection.
- OnchainOS artifact promotion is fail-closed until license/redistribution approval, pinned provenance/checksum/schema validation, staging canary, and a valid `current.json` pointer all pass.
- Runtime execution is fail-closed: only exact `EXECUTION_DISABLED=false` permits signing, transaction submission, paid requests, live trading, or autonomous/scheduled actions. Absent, empty, true, or malformed values keep Telegram ingress, API, and static dashboard available while execution remains disabled.
- Public dashboard deployment uses `HOST=127.0.0.1`, Cloudflare Tunnel to `http://127.0.0.1:3000`, exact `CORS_ALLOWED_ORIGINS`, `TRUST_PROXY=loopback`, polling (`USE_WEBHOOK=false`), and `EXECUTION_DISABLED=true`. Public health exposes status only; detailed diagnostics and every `/owner/*` route require authenticated owner access.
- Regression gates: `npm test -- --runInBand --no-coverage`; dashboard `npm run build`; xBot Agent API `uv run --python 3.11 --with-requirements requirements.txt python -m pytest tests -q`; syntax-check all tracked/untracked JavaScript with `node --check`; parse all tracked/untracked JSON; `git diff --check`; and scan changed/untracked files for real secrets without printing values.
- Bundled 9Router offline release gate: run `npm run test:offline -- --reporter=json --outputFile=<json>` in both an isolated pre-patch worktree and the candidate with identical Node/dependencies, then run `npm run test:offline:verify -- <baseline-json> <candidate-json>` in the candidate. The explicit offline config excludes `*.real.test.js`, `*.live.test.js`, the absent-cloud-worker test, and the network-dependent xAI OAuth discovery test; historical known failures remain acceptable only when the differential gate reports zero pass-to-fail regressions.
- Tenant-aware database and outbound-proxy initialization is request-scoped and idempotent per tenant; it must never execute from module import or during static build collection.
- Tenant provider actions are an exact allowlist: Antigravity/Gemini CLI use `oauth_redirect` when configured plus pinned-native-client PKCE/state `manual_callback` loopback fallback; Claude uses tenant-bound one-time `manual_code`; Codex uses tenant-bound one-time `manual_callback` accepting only exact HTTP localhost/127.0.0.1 port 1455 `/auth/callback` with `code`+`state`; Cline/Kimchi use body-only `manual_secret`; Cursor uses body-only `manual_secret` with `accessToken` plus `machineId`; Grok Web/Perplexity Web use body-only `manual_secret` with the exact upstream session-cookie value and an explicit sensitive-session warning; OpenCode uses explicit credentialless `free_connection`; MiMo Code Free uses a bounded v0.5.55 `service_probe` and returns typed `UPSTREAM_SERVICE_ENDED` without creating a connection when unavailable. Never scrape browser cookies or local files automatically. Validate before write, redact catalog/response/log output, and remove/disable connections to make tenant-authoritative models empty. Credentials are encrypted with tenant+connection-bound AES-256-GCM using `NINEROUTER_VAULT_KEY`, with a 64-character-or-longer `ROUTER_SECRET` fallback only. Existing plaintext rows migrate on their next bounded repository write; vault-key rotation requires an explicit decrypt-and-reencrypt migration before changing key material.
- The eleven provider icons are byte-preserved local assets from pinned upstream 9Router `v0.5.55`; their only canonical public route is `/xBot/providers/<reviewed-file>`. Vite copies `dashboard/public` into `dashboard/dist/xBot`, and the root server mounts only that artifact at `/xBot`. `dashboard/public/providers/provenance.json` is the regeneration source of truth for upstream path, MIT license, ID mapping, and SHA-256. Regenerate only from that exact tag, never hotlink or fabricate assets, then run icon hash/resolver/build/root-server crawl gates. Resolver aliases are centralized and unrecognized or failed assets use deterministic monograms.
- Dashboard UI brand assets must resolve through `dashboard/xBot/src/utils/assetUrl.js`, which uses Vite `BASE_URL`; HTML metadata uses `%BASE_URL%`, while manifest image paths are rooted under `/xBot/`. Never use root-only `/xbot-logo.png`, `/logos/*`, `/icons/*`, or `/manifest.json` URLs.
- 9Router provider reconciliation is metadata-first and additive: inventory the exact upstream registry at a pinned read-only revision, verify origin/version/MIT license, derive canonical IDs and auth modes from registry entries, copy only reviewed provider modules with their upstream copyright/license headers, and import each once. The displayed provider inventory is the exact unique ID set returned by a freshly built production standalone after the active bundled registry's `hidden` filter; device-code inventory includes only callable `device_code` handlers exposed by current tenant routes. Review/regenerate `services/nine-router-sidecar/tests/fixtures/provider-catalog.inventory.json` from `buildTenantProviderCatalog()`, then run `npm --prefix services/nine-router-sidecar run test:catalog-parity` to build the production standalone and assert signed-HTTP source/runtime ID parity, alias uniqueness, and the eight reviewed API-key additions. Never change the fixture only to satisfy a count. The frozen eleven-provider action matrix above is the reviewed exception to the default metadata-only policy; all other cookie, local callback, public redirect, manual, and import flows stay `unavailable` with a precise reason until tenant-safe infrastructure exists. Provider registry models never populate `/v1/models`; that endpoint remains derived only from active tenant connections and explicitly enabled models. Re-run the tenant HTTP harness, offline differential gate, builds, redaction/secret scans, and license/header checks after every reconciliation.
- PM2 release activation must not use restart/reload to change releases because those operations preserve the entry's old cwd/script. Use the corrected release-local ecosystem definition targeting its absolute `safe-wrapper.js`, obtain explicit approval before replacing only the `xbot` entry, then read back exactly one entry's absolute `pm_cwd`, `pm_exec_path`, and live command line. Run `pm2 save` only after all release QA passes, and read back the PM2 dump to verify the same unique staged identity without exposing environment values.
- Provider-OAuth production deployment is fail-closed at preflight: the pinned upstream public/native OAuth client is loopback-only and cannot authorize the xBot HTTPS callback. Directly inspect the active secret sources and both process environments using boolean-only output, require all provider client variables, an acceptable vault key/fallback, the exact public origin, sidecar propagation, and owned callback-registration evidence before transfer or build. Before activation, use only mocked authorization/token/model upstreams to prove one-time PKCE callback exchange, tenant-bound encrypted storage/catalog/model discovery/chat, refresh-and-single-retry, typed revoked/malformed errors, and replay/wrong-tenant/provider/session rejection without duplicate connections or calls. Real consent and paid inference remain user-run validation and are never inferred from mocks.
- Custom OpenAI/Anthropic-compatible provider nodes are LLM-kind candidates, but `/v1/models` exposes only authoritative dynamic or explicitly enabled models from an active connection for the same tenant; disconnected, disabled, deleted, or cross-tenant nodes expose none, with no static registry fallback.
- Codex model discovery uses the same shared live resolver for `/v1/models` and `/api/providers/:connectionId/models`, including tenant-scoped account headers and connection proxy policy; do not make xBot aggregate management endpoints as a second model authority.
- A staged release must never link a startup-critical SQLite file through the mutable `current` symlink: after activation that becomes a self-referential path and SQLite fails with `SQLITE_CANTOPEN` before the API binds. Point candidate state to a verified non-self-referential immutable/shared absolute path, then gate activation with `readlink -e`, SQLite `quick_check`, and a bounded fail-closed startup probe on an isolated port/data path.
